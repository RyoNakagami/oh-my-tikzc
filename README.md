# oh-my-tikzc

[日本語](README-jp.md)

Architecture documentation for people, generated from code by Claude Code or Codex and rendered with [tikzc](https://github.com/RyoNakagami/tikzc).

The skill turns a repository into a set of architectural perspectives, drills into complex components, and keeps editable TikZ diagrams beside their explanations and source references. It adapts the perspective-based approach of [oh-my-mermaid](https://github.com/oh-my-mermaid/oh-my-mermaid): the same `.omm/`-style tree, field vocabulary, and recursive drill-down, with tikzc in place of Mermaid and a bundled checker in place of the `omm` CLI.

![tikzc overall architecture, generated by this skill](docs/architecture.svg)

*tikzc's own overall architecture (Japanese), generated by this skill. Browse the [full example](examples/tikzc/.omtkc/index.md), a snapshot of tikzc v1.2.1.*

For a full walkthrough, see [Getting started](docs/getting-started.md) and [How it works](docs/how-it-works.md).

## What you get

- An overview plus useful perspectives such as data flow, command dispatch, and external integrations.
- A `.omtkc/` directory tree of components, with relative Markdown links from overview to detail.
- `.tikz` sources, SVG/PNG renders, and explanations grounded in source files.
- A `meta.yaml` per component recording its source files, children, analyzed commit, and render state.
- A checker, `omtkc.py`, that validates the tree and finds components whose sources changed since the last analysis.
- Updates that preserve human notes and untouched subtrees.

This is a skill package, not a renderer or an installed CLI. Rendering uses the separately installed tikzc executable. There is no cloud service, account, upload command, or hosted viewer. Documentation and rendering stay in local files; your chosen AI tool still operates under its own data and network settings.

| oh-my-mermaid | oh-my-tikzc |
| --- | --- |
| `.omm/` with `meta.yaml` | `.omtkc/` with `meta.yaml` ([format](skills/tikzc-architecture/references/format.md)) |
| `omm validate`, `omm refs` | `omtkc.py check` |
| `omm tree`, `omm status` | `omtkc.py tree` |
| `omm diff` | `git diff` and `omtkc.py stale` |
| `omm view` web viewer | Markdown preview with relative links |
| Cloud push/pull/share | Not included |

## Prerequisites

Install the Rust-native [tikzc CLI](https://github.com/RyoNakagami/tikzc#installation) and [uv](https://docs.astral.sh/uv/getting-started/installation/), and verify that both are on PATH:

```sh
tikzc --version
uv --version
```

**tikzc 1.2.0 or later is required.** Earlier releases, including the pre-1.0 TypeScript/TeX pipeline, are not supported. tikzc renders natively, with embedded fonts and no TeX toolchain. The skill checks the actual installed CLI and reports unsupported syntax rather than switching renderers.

uv runs the bundled checker and fetches its single dependency (PyYAML) on first use. Installing tikzc, uv, and that dependency can require network access; rendering and checking do not.

Without uv, the checker also runs with `python3` (3.10 or later). It uses PyYAML if installed and otherwise a built-in parser for the YAML subset that `.omtkc/` uses (see [format.md](skills/tikzc-architecture/references/format.md#yaml-subset)).

## Install the skill

This repository is a plugin marketplace for both tools. Its single plugin, `oh-my-tikzc`, contains the `tikzc-architecture` skill.

For **Claude Code**:

```sh
claude plugin marketplace add RyoNakagami/oh-my-tikzc
claude plugin install oh-my-tikzc@oh-my-tikzc
```

For **Codex**:

```sh
codex plugin marketplace add RyoNakagami/oh-my-tikzc
codex plugin add oh-my-tikzc@oh-my-tikzc
```

Start a new session in the repository you want to document after installation. To update, run `claude plugin marketplace update oh-my-tikzc` and then `claude plugin update oh-my-tikzc@oh-my-tikzc`, or run `codex plugin marketplace upgrade oh-my-tikzc`.

Both tools read the same `SKILL.md`; `.codex-plugin/plugin.json` and `agents/openai.yaml` add Codex UI metadata. No provider-specific tool names, hooks, or permission overrides are required.

### Manual install

To install without a marketplace, or for a single project, copy the **whole** `skills/tikzc-architecture/` directory, including `references/`, `assets/`, `scripts/`, and `agents/`. Copy it to `~/.claude/skills/` (Claude Code) or `~/.agents/skills/` (Codex) for a personal skill, or to the target project's `.claude/skills/` or `.agents/skills/`. From the root of this repository:

```sh
mkdir -p "$HOME/.claude/skills"
test ! -e "$HOME/.claude/skills/tikzc-architecture" && test ! -L "$HOME/.claude/skills/tikzc-architecture" && cp -R skills/tikzc-architecture "$HOME/.claude/skills/"
```

The `test` guards stop if a same-named installation already exists; for an update, compare and back up that installation first. Placement follows the official [Claude Code skills](https://code.claude.com/docs/en/skills) and [Codex skills](https://learn.chatgpt.com/docs/build-skills) documentation. A manually installed skill is invoked without the `oh-my-tikzc:` prefix shown below.

## Use

In Claude Code:

```text
/oh-my-tikzc:tikzc-architecture Explain this repository's architecture in Japanese.
```

In Codex:

```text
$oh-my-tikzc:tikzc-architecture Explain this repository's architecture in Japanese.
```

You can also ask naturally to map a codebase with tikzc. Scope the request when needed:

```text
Use tikzc-architecture to document only the request lifecycle of src/api/.
Refresh the existing .omtkc documentation for the changes in the CLI module.
```

The default output is `.omtkc/` in the analyzed repository:

```text
.omtkc/
  config.yaml                  # schema and language
  index.md                     # entry point
  overall-architecture/        # a perspective
    description.md
    meta.yaml                  # sources, children, refs, analyzed commit, render state
    diagram.tikz               # groups have a diagram
    diagram.svg
    diagram.png
    compiler/                  # one directory per diagram node
      description.md
      meta.yaml
      diagram.tikz
      diagram.svg
      diagram.png
      text-engine/
        description.md         # leaves need no diagram
        meta.yaml
```

Open `.omtkc/index.md` in a Markdown preview and follow links into the details. Each group embeds its SVG and links to its children and editable source. This is static document navigation; SVG nodes are not interactive drill-down controls. The optional tikzc VSCode extension provides source preview and editing.

**Commit `.omtkc/`** with your code. Diagram history is then ordinary `git diff`, and the next refresh can find what changed since each component was analyzed.

The skill compiles and renders each changed diagram, inspects its PNG when an image-reading tool is available, and runs the checker. It reports missing compiler or visual validation explicitly. Architectural findings still need human review: diagrams explain the code that was inspected, not a formally verified specification.

### The checker

The skill runs these itself; you can also run them directly. `<skill>` is the installed skill directory, for example `~/.claude/plugins/cache/oh-my-tikzc/oh-my-tikzc/<version>/skills/tikzc-architecture` (Codex: under `~/.codex/plugins/cache/`), or `~/.claude/skills/tikzc-architecture` for a manual install.

```sh
uv run <skill>/scripts/omtkc.py check .omtkc   # structure, links, sources, stale renders
uv run <skill>/scripts/omtkc.py tree .omtkc    # hierarchy and render state
uv run <skill>/scripts/omtkc.py stale .omtkc   # components whose sources changed since analysis
```

Without uv, replace `uv run` with `python3`.

`check` verifies that diagram node IDs match child directories, navigation links resolve, recorded source files exist, refs are mutual, and each SVG/PNG was rendered from the current `.tikz`. It cannot tell whether an arrow is true.

## Package development

The canonical skill is in [`skills/tikzc-architecture/`](skills/tikzc-architecture/SKILL.md). [`examples/tikzc/.omtkc/`](examples/tikzc/.omtkc/index.md) is its output for tikzc, kept as a snapshot: its `config.yaml` names the source repository and commit, and its source links are permalinks to that commit.

Run the checker tests:

```sh
uv run --with pyyaml python -m unittest discover -s tests
```

Run `python3 -m unittest discover -s tests` without PyYAML to exercise the built-in YAML parser; the comparisons against PyYAML are then skipped.

Check the template and render a preview:

```sh
tikzc check skills/tikzc-architecture/assets/architecture.tikz
tikzc skills/tikzc-architecture/assets/architecture.tikz -f both -o /tmp/oh-my-tikzc-preview/
```

Inspect the PNG after changing the template. Test skill changes on a real codebase, including a refresh after a code change, and check source evidence, child links, preserved notes, and diagnostic handling. This package does not ship tikzc binaries or install skills automatically.
